# Node.js Agent 课程打磨计划

这份文档记录课程定位、统一教学标准、视频制作流程和交付顺序。能直接用于某一章的教程、练习和脚本，放在对应章节的 `docs/` 中。

课程总介绍和 13 章目录已整理在项目根目录 `README.md`。第一章已完成请求与响应主题的教程、23 页 PPT 和 4 段视频样章；视频使用火山引擎豆包语音合成，音色为刘飞 2.0，附同步字幕和独立音轨。页内旁白连续播放，只在翻页处停顿 1 秒；字幕使用无底色白字，清理句尾标点和口语化技术词。课件以整页画面为底，代码重点可逐次点击高亮。每页内容和旁白源稿保存在 `lesson01-minimal-agent/docs/media/manifest.json`，生成流程和文件入口见该章 `docs/media/README.md`。

面向刚接触 Agent、只有少量 Node.js 经验的读者，新增了[入门者学习指南](beginner-guide.md)和[逐章练习册](beginner-practice.md)。新教程的阅读路径是：先运行、跟一条数据流、读关键代码、观察失败、再做练习。章节原有的深入实现说明保留为参考内容；第一次学习时可先按指南中的章节重点阅读。

第二章已补充一份请求与响应教程，并修正了工具流水线顺序、未声明安全等级时默认放行、循环签名受对象键顺序影响、整数参数有损截断等问题。第二章 PPT 和视频仍待制作，后续按第一章样片的节奏，把工具匹配、校验、权限确认、执行和结果回填逐步展示出来。

## 课程定位

### 一句话介绍

从最小 Agent 循环开始，用 Node.js 一步步实现工具调用、上下文管理、记忆、协作、扩展和运行治理，理解一个 Agent 是怎样工作的。

### 学习者

课程面向会基础 JavaScript、想掌握 Agent 实现原理的开发者。学习者需要了解函数、对象、数组、Promise、`async/await`、ES Modules 和命令行；不要求先掌握特定 Agent 框架。Node.js 18+ 是代码环境要求。

真实调用模型需要一个兼容 OpenAI Chat Completions 的服务。章节测试使用假模型或本地替身，减少对密钥、网络和调用费用的依赖；具体前置条件以对应章节 README 为准。

### 对外介绍文案（工作稿）

你会从一个最小的 Agent 开始，亲手看清模型如何提出工具调用，程序如何执行工具、处理结果，再把结果交回模型。接下来，你会逐步为它加上上下文管理、长期记忆、任务委派、Skill、Plugin、MCP、多会话和消息接入，最后补上重试、熔断、流式输出、观测与评测。

每个主题都对应一份可运行的 Node.js 代码。你不只会知道某个术语是什么，还能沿着调用链找到它在哪一行发生、为什么要这样设计，以及下一步可以怎样修改。

适合希望理解 Agent 内部机制、并能自己搭建和调整实现的 Node.js 开发者。课程要求有 JavaScript 基础，不是编程零基础课程。完成课程后，你将拥有一套可运行的 Agent 学习项目，以及继续接入具体模型和业务的架构基础。

正式销售页后续还需要补上真实的授课者介绍、视频样片、课程时长、更新方式、价格和服务说明；这些信息目前没有确定，不在文案中虚构。

## 教学主线

课程按能力逐步展开，保持“遇到一个问题，再添加一项机制”的节奏：

| 阶段 | 章节 | 学习者在解决什么问题 |
|---|---|---|
| 建立 Agent 骨架 | 1–4 | Agent 循环如何工作；如何定义、校验和执行工具；上下文如何受控 |
| 增加 Agent 能力 | 5–9 | 如何记忆、委派任务、按需加载知识、扩展生命周期和接入外部工具 |
| 接入运行环境 | 10–12 | 如何保存对话、接入消息渠道、让 Agent 按计划主动运行 |
| 面向真实使用 | 13 | 如何应对模型故障、观察运行状态并回归检查行为 |

几个容易混淆的概念要通过具体例子讲清楚：MCP 是工具接入协议，Plugin 是扩展 Agent 的代码，Skill 是供 Agent 使用的知识和流程。它们可以协作，但不互相替代。

## 每章的教学包标准

### 1. 章节 README：帮助学习者开始

保留现有 README 的强项，并统一这些信息：

- 本章要解决的问题，以及学完后可以独立完成的事情
- 前置章节和必需环境；区分“跑离线测试”和“连真实模型”
- 从课程根目录可复制执行的命令
- 只列本章新增或关键修改的文件；继承文件提供链接或简短说明
- 一张“本章新增什么、为什么需要”的表
- 最多几个最常见的运行问题和解决办法

行数、测试数量、逐字节复制情况和完整测试列表留给愿意深挖的读者，避免挡住初学者的第一步。

### 2. `docs/course.md`：讲明白实现

按下面顺序组织内容。概念首次出现时用短例子解释，再逐渐落到实际代码：

1. **问题场景**：先让学习者知道没有这项能力会发生什么。
2. **本章模型**：用一张小图或一段流程说明参与者和数据怎么流动。
3. **最短运行路径**：给出命令、预期现象和观察重点。
4. **关键代码**：从入口跟到机制发生的位置，解释关键变量、边界和取舍。
5. **自己改一次**：一个可完成的小练习，写明目标、起始文件和完成标准。
6. **回顾与下一章**：用几句话收束本章，并指出接下来要解决的新问题。

原则是“一段解决一个问题”：不要把整份文件逐行复述；讲清数据如何经过代码、为什么做出这个设计、学生可以怎样验证理解。完整 API、所有测试条目和面试题仍可保留在参考文档。

### 3. 练习：从看懂走到会改

每章先提供一个主练习，难度控制在能基于本章代码完成的小改动。练习说明至少包含：

- 目标和所需起始代码
- 建议修改的文件
- 完成后可观察到的行为
- 自查方法或提示

答案可以单独放在 `docs/solutions/`，或在课程交付时作为单独答案包提供。练习不应要求额外购买服务才能完成。

## 视频制作规范

### 讲解形式

采用“少量 PPT + 代码/终端录屏 + AI 中文旁白 + 校对字幕”。PPT 负责画出概念和流程，代码录屏负责讲清实现，终端录屏展示结果。代码课不建议全程只展示静态 PPT。

无需一开始制作 AI 数字人。对这门课程，清晰的代码画面、自然的中文声音和准确字幕比虚拟讲师更重要。可以先做旁白型视频样片，确认学习体验后再决定是否加入讲师形象。

### 每章视频结构

每章按内容拆成若干个短片，每段集中讲一个问题：

1. **本章问题与地图**：为什么要学、这章放在全课程哪里。
2. **概念与流程**：用 PPT 图示建立直觉。
3. **关键代码**：打开真实文件，沿执行路径讲解。
4. **运行演示与练习**：展示输入、输出、一个常见失败或练习入口。

不强求每章固定片数。若一个主题讲不完，拆开比加快语速更好。每段开头告诉学习者这段要解决什么，结尾复述一条可以带走的结论。

### 可复用的视频生产流程

1. 以章节教程和实际代码为准，先写分集大纲；不要让视频工具自行改写技术事实。
2. 为每段写逐页旁白稿和画面说明。PPT 页面只留关键词、结构图和必要代码，详细解释放在旁白。
3. PPT 的演讲者备注写入最终确认的旁白稿，逐页生成 AI 配音。
4. 插入录屏片段，调整页面和代码画面的停留时间。
5. 生成字幕后逐句校对，重点检查代码标识符、英文缩写、数字和中英文切换。
6. 导出成片和字幕文件；以实际代码重跑画面中的命令，核对视频版本与章节代码一致。

推荐每章保留：`docs/video-outline.md`（分集结构）、`docs/video-script.md`（旁白和镜头脚本）；如有必要，再保存独立字幕文件。避免把未经校对的机器转写字幕当成最终教学资料。

### AI 视频工具初选

目前可以先比较两条 PPT 旁白路线：

- [Synthesia：导入 PowerPoint](https://docs.synthesia.io/docs/import-powerpoint)：官方文档说明演讲者备注可作为脚本，幻灯片元素可编辑；导入时不会保留 PowerPoint 动画。适合已有 PPT、希望逐页编辑和配音的样片。
- [HeyGen：PowerPoint 转视频](https://www.heygen.com/en-gb/tool/powerpoint-to-video)：官方页面介绍了导入演示文稿、旁白和字幕的工作流；其[幻灯片视频工具说明](https://www.heygen.com/en-au/tool/ai-slide-show-maker)提到可导出 SRT。适合快速验证整套生产流程。

建议各用第一章同一段 3–5 分钟内容做小样，比较中文发音、字幕修改成本、代码画面清晰度、导出格式和后续修改便利度。工具套餐、价格与地区支持会变化，决定长期使用前再对照官方信息和自己的账号实测。这里不预设必须购买哪一家。

## 第一章样板与后续顺序

第一章适合做样板，因为它代码量最少，Agent 循环和 Function Calling 的核心过程都能直接展示。当前版本按普通问答、工具调用请求、本地执行与回填、最终回答和代码走读组织。教程、逐页脚本、PPT、视频、字幕和重建方法分别放在 [`lesson01-minimal-agent/docs/`](../lesson01-minimal-agent/docs/) 与 [`lesson01-minimal-agent/docs/media/README.md`](../lesson01-minimal-agent/docs/media/README.md)。

接下来按这个顺序打磨：

1. 用第一章验证教程结构、练习难度、旁白语气和屏幕录制节奏。
2. 根据样片反馈，整理统一的章节 README、教程和视频脚本模板。
3. 制作第 2 章 PPT 与视频，再精修第 3–4 章，让学习者建立工具、上下文和真实工具使用的基础。
4. 再按“Agent 能力 → 运行环境 → 生产化”推进其余章节，并优先讲本章增量，避免重复讲整套继承代码。
5. 完成全书一致性复核：章节编号、路径、Node 版本、配置、术语、前后衔接和未完成内容标记。

## 课程交付前的检查点

- 对外承诺与仓库实际内容一致；不把示例实现说成可直接承载任意生产业务的系统。
- 学习者能在不看完整答案的情况下，按教程启动项目并完成一项本章练习。
- 代码演示、命令输出和视频字幕与对应章节版本一致。
- 章节说明区分离线测试、模型服务和第三方平台凭证等不同条件。
- 价格、课时、更新承诺和售后政策只在确定后写入销售页。
