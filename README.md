# Node.js 手写 AI Agent：从工具调用到生产化

**先看懂一次模型请求，再亲手搭出一个能调用工具、管理上下文并持续运行的 Agent。**

模型说“我去查一下天气”，天气 API 并不会因此自动运行。程序还要读懂模型的 `tool_calls`，按工具名找到本地实现，执行后把结果写回 `messages`，再请求模型。本课程从这段最小闭环出发，逐步增加校验、记忆、协作、扩展和运行治理，让每个关键机制都能在 Node.js 代码里找到、运行和修改。

## 你将学会

- 沿着请求与响应读懂 Agent 主循环，分清模型的调用意图和程序的本地执行
- 为工具增加注册、参数校验、错误处理和权限确认
- 控制对话上下文长度，并实现摘要压缩与可持久化记忆
- 拆分子任务，按需加载 Skill，并通过 Plugin 和 MCP 扩展工具能力
- 保存会话、接入消息渠道、设置定时任务
- 为模型调用增加重试、熔断、流式输出、运行观测和行为评测

最终代码会从一个最小 Agent 逐步扩展为可继续接入模型与业务的 Node.js 项目。课程重点是帮你理解设计与实现；生产接入仍需根据业务补充部署、数据存储、安全和运维方案。

## 这门课怎么教

每章围绕一个真实的工程问题展开：先看问题和运行现象，再沿调用路径读关键代码，最后自己改一项能力。课程提供逐章 Node.js 代码包、教程、练习和离线验证方式；代码示例尽量不依赖特定 Agent 框架，让你看到协议字段和关键逻辑实际在哪里发生。

第一章提供了逐轮代码教程，拆解请求、响应和消息历史。可以从[第一章导读](lesson01-minimal-agent/docs/request-response-walkthrough.md)开始，再阅读章节正文。

### 第一部分：搭好 Agent 的骨架

| 章 | 内容 | 这一章解决的问题 |
|---|---|---|
| 01 | 最小 Agent 循环 | 模型怎样决定调用工具，程序怎样执行并回填结果？ |
| 02 | 工具系统 | 参数错了、工具不存在或操作有风险时怎么办？ |
| 03 | 上下文管理 | 对话越来越长，怎样控制 token 并保留关键信息？ |
| 04 | 核心工具 | 怎样让 Agent 搜索、读写文件并访问外部信息？ |

### 第二部分：让 Agent 有记忆、会协作、能扩展

| 章 | 内容 | 这一章解决的问题 |
|---|---|---|
| 05 | 记忆与召回 | 怎样从对话中提取信息，在之后的对话里找回来？ |
| 06 | 多 Agent 委派 | 怎样把子任务交给隔离的子 Agent，再汇总结果？ |
| 07 | Skill 系统 | 怎样把领域知识按需交给 Agent？ |
| 08 | Plugin 与 Hooks | 怎样在工具执行前后加入可扩展逻辑？ |
| 09 | MCP | 怎样通过标准协议接入另一个进程提供的工具？ |

### 第三部分：让 Agent 能持续运行

| 章 | 内容 | 这一章解决的问题 |
|---|---|---|
| 10 | 多会话与保存恢复 | 怎样保存对话，并在重启后继续使用？ |
| 11 | 消息网关 | 怎样接入终端和 QQ 等消息渠道？ |
| 12 | 定时任务 | 怎样让 Agent 在设定时间主动执行任务？ |
| 13 | 生产化基础 | 怎样处理模型故障、流式输出、运行观测和行为评测？ |

几个容易混淆的概念会用具体代码区分：MCP 是外部工具接入协议，Plugin 是扩展 Agent 生命周期的代码，Skill 是帮助 Agent 完成任务的知识和流程。它们可以协作，但解决的问题不同。

## 适合谁

- 会写基础 JavaScript，想理解 AI Agent 内部工作方式的开发者
- 已经调用过大模型 API，想从“会请求模型”走到“能搭建 Agent”的学习者
- 希望系统学习工具调用、上下文、记忆、MCP 和工程化取舍的 Node.js 开发者

本课程不是 JavaScript 入门课。建议先熟悉变量、函数、对象、数组、Promise、`async/await`、ES Modules 和命令行操作。Node.js 版本要求为 18 或更高。真实对话需要兼容 OpenAI Chat Completions 接口的模型服务；各章测试使用假模型或本地替身，具体前置条件以章节 README 为准。

## 从第一章开始

如果你刚开始接触 Agent，先看[入门者学习指南](docs/beginner-guide.md)：里面有运行顺序、常用术语和每章的阅读重点。

### 本地打开 VitePress 教程站

在项目根目录安装文档站依赖并启动本地预览：

```bash
npm install
npm run docs:dev
```

终端会显示本地访问地址。正式构建和预览分别使用 `npm run docs:build`、`npm run docs:preview`。章节代码仍在各自的 `lesson...` 目录中；教程站直接展示这些 Markdown 文档，改动教程时不需要维护第二份副本。

推送到 GitHub 的 `main` 分支后，GitHub Actions 会构建 VitePress，并部署到 GitHub Pages。首次发布时，在仓库的 Pages 设置中把发布来源设为 GitHub Actions。

```bash
cd lesson01-minimal-agent
npm test
```

测试通过后，按章节 README 配置模型服务，再启动真实对话：

```bash
node main.js
```

各章分别位于 `lesson01-*` 至 `lesson13-*` 目录，包含 README、教程、练习或复习资料及对应代码。课程定位、教学规范和后续制作计划见 [`docs/course-plan.md`](docs/course-plan.md)。
